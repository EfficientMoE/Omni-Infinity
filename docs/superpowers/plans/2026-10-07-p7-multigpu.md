# P7 — Multi-GPU serving on 6× RTX PRO 6000 Blackwell (PCIe)

Tracking: [#42](https://github.com/EfficientMoE/Omni-Infinity/issues/42) (P7).
Refs: [t2v survey](../../t2v_optimization_survey.md) §4, ARCHITECTURE.md,
reuse scan on #42.

## Objective

Move beyond the single-GPU, single-worker design (`OMNI_WORKERS=1`
contract) in two phases: (1) stage pipelining + CFG parallel for
multi-request throughput, (2) USP sequence parallelism + parallel VAE for
single-request latency. PCIe-class interconnect assumptions throughout.

## Phase 0 — platform validation (prerequisite checklist)

RTX PRO 6000 supports PCIe P2P (GeForce does not), but requires host
config. Produce `docs/multigpu_platform.md` with measured results:
- [ ] BIOS: IOMMU **off** (not just passthrough), ACS off
- [ ] `options nvidia_uvm uvm_disable_hmm=1`; `ForceP2P` registry override
- [ ] `nvidia-smi topo -m` + `p2pBandwidthLatencyTest` matrix
- [ ] `nccl-tests` all_gather/all_to_all with `NCCL_P2P_LEVEL=SYS`,
      `NCCL_MIN_NCHANNELS=8` (expect ~40 GB/s class vs ~22 untuned)
- [ ] Fallback documented: `NCCL_P2P_DISABLE=1` (−30 % collectives)

## Phase 1 — stage pipelining + CFG parallel (throughput)

- **Stage pipelining across GPUs**: generalize the existing single-worker
  pipelined multi-prompt demo (`omni_infinity/demo/pipeline.py`) into
  encoder / denoiser / decoder *roles* on separate devices with an async
  handoff queue (latents/embeds device-to-device). Donor patterns:
  SGLang-diffusion disaggregation roles; MoE-Infinity
  `expert_offload_coordinator.py` (UnifiedTransferScheduler) and
  `core/memory/stream_pool.h` for copy/compute stream discipline.
  Serving contract change: `OMNI_WORKERS` stays 1 *per role*; the profile
  gains `OMNI_ROLE={all,encoder,denoiser,decoder}` + device map. HTTP 409
  profile-mismatch semantics unchanged.
- **CFG parallel**: if/where H3 uses CFG (verify in the modular pipeline —
  xDiT marks MiniMax CFG unsupported, so this is a conditional work item),
  run cond/uncond on two denoiser GPUs with a latent all-gather per step.
  If H3 has no standard CFG: drop, note in #42.
- Memory upside: with 96 GB per role, encoder and denoiser can run fully
  resident (no streaming) → stage latency drops below the 22 GiB-envelope
  numbers; keep streamed single-GPU mode as the budget profile.

## Phase 2 — USP + parallel VAE (latency)

- **Ulysses-first** sequence parallel on the denoiser group (degree ≤4 on
  PCIe; all-to-all volume shrinks with degree, Ring's does not). Reference
  implementations: xDiT `xfuser` USP, para-attn context parallel; integrate
  at the attention-call seam used by P3's backend dispatch.
- **Parallel VAE**: spatial-shard (halo-exchange) decoder preferred over
  overlap-tiling (exact, no seams) — donor: vllm-omni Wan spatial shard;
  temporal chunking for the audio/video VAEs if causal.
- Compose: CFG×Ulysses mesh only after both work independently.

## Verification

Goldens unchanged per stage (handoff is data-movement only → bitwise);
USP tier documented separately. Throughput: VidProM/multi-prompt trace
jobs/hour; latency: s/NFE and end-to-end at 256p/120f per topology.

## Risks

- P2P platform issues (dual-socket hangs) → Phase 0 gate before any code.
- torch.distributed inside the job server complicates the one-process
  serving model → run roles as separate processes with a thin RPC/queue
  (MoE-Infinity `expert_executor.py` rpc pattern), not in-process TP.
- USP intrusion into third_party VDN attention → confine to the dispatch
  seam built in P3; if upstream resists, stage pipelining alone still
  delivers the throughput win.
